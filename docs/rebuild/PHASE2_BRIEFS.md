## Common rules (every builder)

1. **Own only your files** (listed in your brief and in REBUILD_PLAN §5). Anything you need in a shared file (`main.py`, `styles.css`, `api.js`, `ui.js`, `seed.py`, `seed_v2.py`, `features.py`, `DESIGN_SYSTEM.md`, someone else's module) goes in `docs/rebuild/<builder>_integration.md` with the exact change. The lead applies it.
2. Other builders edit other files in the same working tree at the same time: never `git stash/checkout/reset/clean/restore`, never `git add -A` / `git add .`, never reformat files you don't own.
3. **Style:** plain HTML/CSS/JS in `web/` (no build step, no frameworks). External libraries only from cdnjs or jsdelivr with exact versions (three.js **0.169.0**, qrcodejs **1.0.0**). Use the design tokens and components in `web/css/styles.css` and `web/js/ui.js` (`SB.ui.*`, `SB.api.*`, `SB.auth.*`). Page-only styles go in your own `web/css/<area>.css`. Escape every user string with `SB.ui.esc`. Status badges only via `SB.ui.badge(featureKey)` / `data-feature="<key>"`, with keys that exist in `backend/app/features.py` (a test checks this; ask for a missing key in your integration note).
4. **Hospital pages** live in `web/hospital/`, call `SB.ui.boot('<navKey>')`, and need a staff login. **Patient-side pages** follow DESIGN_SYSTEM §6 and FEATURE_PLAN Part D: ≥ 20 px text, 64–72 px targets, one action per screen, at most 3 big options, icons + words, no English-only text.
5. **Backend:** FastAPI `APIRouter` in your own module (the module name is pre-registered in `main.py`, so creating the file is enough; restart the server to load it). Every handler calls `authz.require(action, pid)` (action names: REBUILD_PLAN §3.3). Path params use the names in REBUILD_PLAN §3.4 item 11. Every write calls `audit.write(...)`. Times in IST (`config.now_local()`), ISO with offset.
6. **Safety rules are code, not hope:** AI never diagnoses or advises; no dose events before a human approves; SOS never scheduled; patient taps are "reported", never "taken"; red-flag words → the fixed message "Please contact your nurse now. In an emergency call 112."; medicine questions → "Please ask your doctor or nurse"; nothing about payment anywhere; fake data only; obey the never-say lists (spec §2).
7. **Honesty labels:** every feature shows Live / Simulated / In development / Planned from the registry. Nothing Planned looks clickable.
8. **Tests:** your own `tests/test_<area>.py` (pytest, FastAPI TestClient via the fixtures in `tests/conftest.py`: `client` = demo admin, `login_as(email)`, `anon`). Mock every external service. Run your tests plus `tests/test_isolation.py` (it walks every route, including yours). Never delete or weaken a test.
9. **Browser check** before you finish: `MSYS_NO_PATHCONV=1 .venv/Scripts/python.exe tools/qa/browser_check.py --role <role> <pages…> --out <scratch dir>` (starts its own server; 375 + 1440 px, light + dark; reports console errors, failed requests, sideways scroll; saves screenshots – look at a few with the Read tool). Fix what it finds. Write your own Playwright snippets for real clicks when needed (`from playwright.sync_api import sync_playwright`, `p.chromium.launch(channel="chrome")`).
10. **Commit** only your files when green: `git add <files> && git commit -m "<msg>" -m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>" -- <files>` (retry if `.git/index.lock` exists). Never push.

## B3 – Medicines backend (P2-B3a–c; B3d = P1)

**Spec:** §2 (patient safety), §5 (AI, Principle, Reminders rows), §8.7 (four paths, review rules, the normaliser table – every row), §8.8 (dose states, patient card text, missed-dose alert + family notice with consent), §11 (Gemini – use `ai_gemini.extract_prescription`), §17 (medicine tests).
**Owns:** `backend/app/meds/__init__.py`, `backend/app/meds/normalise.py`, `backend/app/meds/service.py` (REBUILD_PLAN §3.12 functions), `backend/app/meds/pipeline.py`, `backend/app/routes_meds.py` (Contract H + `/api/me/doses/*`, `/api/me/prescriptions` + the three demo routes), `web/js/meds-ui.js`, `tests/test_normalise.py`, `tests/test_meds.py`.
**Build (P0):**
- **Normaliser** (deterministic, pure functions): every row of the §8.7 table, times from the patient's routine (`patients.routine` or the hospital default): OD/QD/once daily/1-0-0 → breakfast; 0-0-1/HS/at night → dinner (HS = bed); BD/BID/1-0-1 → breakfast + dinner; TDS/TID/1-1-1 → breakfast + lunch + dinner; QID/QDS/1-1-1-1 → 08:00, 12:00, 16:00, 20:00; AC/before food → 30 min before the meal time; PC/after food → at the meal time (shown "after food"); ½ / 1½ quantities; SOS/PRN/if needed → never scheduled; STAT → not scheduled + flag "ask the clinician"; "x 5 days / for 1 week / 1 month" → end date; "continue / till next visit / no duration" → needs a human choice; weekly / alternate days → those days. Anything unrecognised → that field unclear (blank + listed in `unclear_fields`), never guessed. If the AI draft and the normaliser disagree → unclear.
- **Pipeline:** the four arrival paths (§8.7): typed by a doctor = approved on save; doctor upload → Gemini draft (`ai_gemini.extract_prescription`, only when `ai_allowed`; handwritten + `ai_handwriting` off → keep the photo, no draft lines, warning "Handwritten – please type the lines") → review → approve; patient upload → `needs_review`, the patient sees "Your nurse is checking your prescription. Reminders start after that."; manual typing whenever AI is off, failed, has no key, is over a limit or the patient chose no AI. Upload validation via `storage.validate_upload`, stored as a `documents` row (kind prescription) via `storage.save`. Warnings (§8.7 list) computed in code (fuzzy name match against the patient). Approve requires every line confirmed/removed and the approver allowed (`rx.approve`, nurse rule + hospital setting); records reviewer + time and `ai_register.record_review(...)` (lines edited/removed counts); then builds dose events. Reject, stop, modify (new version superseding the old, history kept).
- **Doses:** dose events for today and tomorrow from approved scheduled items only (refresh idempotently on `tick(now)`; call `tick` lazily, at most every 30 s, from the read endpoints, and write the exact one-line hook for the comms ticker in your integration note). States upcoming → due → reported_taken | missed (after `grace_minutes`) | paused (programme paused) | cancelled (stopped).
