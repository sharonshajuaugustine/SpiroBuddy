# Roles – how work is split between subagents

The lead session (senior engineer) owns the contracts in ARCHITECTURE.md, starts the subagents, joins their work together, tests end to end and updates the docs. Subagents work **in parallel, each only in its own folders**, and must follow the contracts exactly. **Everything is DEMO for now** (fake patients, no login). The patient mobile app is out of scope: the user builds it separately.

| Agent | Folder(s) | Builds | Done when |
|---|---|---|---|
| **1. Firmware & Hardware engineer** | `firmware/`, `docs/HARDWARE.md` | An Arduino sketch for ESP32 *or* Arduino Uno/Nano, VL53L0X *or* VL53L1X (switch by `#define`), serial contract A, optional buzzer on `B`. HARDWARE.md: wiring tables for each board/sensor combination, library install steps, mounting guide (base vs top, ≥5 cm), calibration steps, troubleshooting. | It compiles in principle (correct library APIs, checked against the web docs) and the docs are complete |
| **2. Backend & data engineer** | `backend/`, `scripts/`, `supabase/`, `render.yaml`, `docs/DEPLOY.md` | FastAPI with contract D, a Store with demo (SQLite, auto-seeded) and Supabase backends, seed data, rules, Claude + template, Twilio + dry run, demo endpoints, static serving of `web/`, run/setup scripts, Render blueprint and deploy guide. | `scripts\run.ps1` starts it, every endpoint answers with no keys, the Supabase path is written against the official client docs, and `render.yaml` is valid |
| **3. ML engineer** | `ml/` | features.py (contract C), synth.py (incl. `make_breath`), train.py → model.joblib + metrics.json, predict.py with `load()` / `predict(features)`. | `python ml/train.py` gives a model with 90%+ accuracy on synthetic data |
| **4. Web (nurse & doctor site) engineer** | `web/` except `web/showcase/` | Dashboard, patient detail, demo control panel, data collection page; api.js, breath.js (contract C), sources.js (serial + simulator), charts. | With the server running, every page works in Chrome in demo mode and updates live |
| **5. 3D & video engineer** | `web/showcase/`, `tools/render/`, `hardware/3d/`, `docs/3D_SOURCES.md` | A Three.js model of the Romsons Breazer 2500 + SpiroBuddy base unit + electronics, built only from cited dimensions. An interactive showroom (orbit, exploded view, X-ray, live breath animation, guided tour) and MP4 videos rendered with headless Chrome + ffmpeg. A GLB export. | The showroom opens at `/showcase/`, the videos play, and every dimension is cited or clearly flagged |
| **6. Research agent (always running)** | `docs/research/` | Continuous, structured research for the pitch: clinical evidence, adherence, competitors, India context, tech validity, regulation, business, vision, judge Q&A. Keeps a URL ledger so no page is read twice; fact-checks our claims. Standing instructions: `docs/research/RESEARCH_PROMPT.md`. | Never 'done': each round ends with an updated KNOWLEDGE_BASE.md + PITCH_FACTS.md; the lead relaunches it with the next gaps |
| **7. Voice & language engineer (Sarvam AI)** | `backend/app/voice*.py`, `backend/app/routes_voice.py`, `web/audio/`, `web/js/voice.js`, `tools/voice/`, `docs/VOICE.md` (+ small separate blocks in web pages) | Sarvam TTS/STT/translate, an 11-language cue library, voice-note summaries, a browser voice player, a red-flag filter on speech. | Endpoints work with and without a key; clips generated when a key exists |
| **8. Communications engineer** | `backend/app/comms/`, `backend/app/routes_comms.py`, `web/guardian.html`, comms JS, additions to dashboard/patient/demo pages, new store tables, `docs/COMMS.md` | Escalation ladder, automated calls (IVR), phone and WhatsApp simulators, alerts inbox, click-to-call, guardian page, WhatsApp quick replies, progress card, trend flag. | FEATURE_PLAN Stage 1 works end to end in dry-run |
| **9. India-fit QA (queued after 7–8)** | review across the repo | Audits demo data, wording, formats, languages, hardware and prices for India; fixes them. | Audit report + fixes |
| **10. Quality & efficiency controller** | `docs/QA_REPORT.md`, `docs/WORK_QUEUE.md` (+ small obvious fixes) | Reviews every finished agent's diff, runs the tests, checks contracts/safety/India-fit/design, hunts waste, and owns the single prioritised work queue. Standing instructions: `docs/QA_PROMPT.md`. | Runs after each build agent and before new launches |
| **Lead (QA & integration)** | everything | Starts the server, clicks through every page, fixes the seams, updates PROGRESS/HANDOFF, commits. | The demo story in REQUIREMENTS §3 passes |

Prompts for each agent should say: read CLAUDE.md + REQUIREMENTS + ARCHITECTURE first, stay inside your folders, check library APIs against the web docs instead of guessing, and report the files created plus how to test them.
