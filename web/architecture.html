Architecture: how the pieces connect

Browser apps talk to one web service. It reads and writes a database and file store, and calls outside services, each with an offline backup. Every box is coloured by its real status, and carries the status word too.

2. The path of a prescription

This is the part that connects the doctor to the patient. The prescription starts as digital data, so no photo has to be read.

  1. The doctor writes it

    In the hospital software, as typed lines. A named person confirms each line before any reminder exists.

  2. It appears on the patient's phone

    Every medicine in plain words and in the patient's language, with reminders. The patient's tap is saved as "reported".

  3. The patient shows it at the counter

    A clear screen for the chemist, and a QR the chemist can scan to compare with the hospital's copy. Pharmacy acceptance is untested.

4. Design rules we keep

Works with no hardware and no keys

Every feature runs in the demo with a breath simulator and offline backups. Real keys and the real unit switch features on without changing the design.

Every AI step has a human backup

If a key is missing, a limit is reached, or the patient chose no AI, the typed or template route is used. The AI never diagnoses and never advises.

The frontend has no build step

Plain HTML, CSS and JavaScript served by the same web service. Libraries come from public content networks with exact versions.

Hospitals stay apart

Every row carries its hospital, and every request is checked for who may see which patient. A stronger check inside the database is Planned.
